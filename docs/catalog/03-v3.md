# Catalog v3（自有目录 canon）

> **状态**：在 `feat/canon` 分支上，未上线。spec 见 [v3-openapi.yaml](./v3-openapi.yaml)（由 `internal/canon/api` 生成，测试保证一致）。v3 只服务 canon 里的条目，第一批是轻小说；galgame 等旧媒介继续走 `/v2`，直到逐个迁入。

## 约定（与 v2 相同）

- 不包信封；错误是 RFC 9457 `problem+json`，按 `code` 判断，不要解析 `title` / `detail`。
- id 是十进制字符串。**canon 与旧库共用 id 空间**：旧库已有的作品、人物名义、组织迁入时沿用旧 id。
- 列表用不透明游标（`cursor` → `next_cursor`）；`ids=` 批量，至多 100 个，不分页。
- 读面带 `ETag`，支持 `If-None-Match`。
- 被合并的 id 回 404，`code=ENTITY_MERGED`，`current_id` 是幸存者；整条下架或被移除的回 410。

## 公开读面

| 路由 | 内容 |
|---|---|
| `GET /v3/catalog/works`、`/works/{id}` | 作品：标题、分卷、署名、书的类别；`medium=` 过滤、`ids=` 批量 |
| `GET /v3/catalog/search?q=` | 按标题找作品 |
| `GET /v3/catalog/releases?isbn=`、`/releases/{id}` | 版本：语言、形态、发售日、ISBN / JAN、出版社与レーベル、收录了哪些卷 |
| `GET /v3/catalog/persons?alias_ids=`、`/persons/{id}` | 人物、全部名义和署名。`alias_ids` 接受旧的 credit name id |
| `GET /v3/catalog/orgs?kind=`、`/orgs/{id}` | 出版社、レーベル等 |
| `GET /v3/catalog/changes` | 变更流，按公开实体命名；镜像和索引跟它走 |
| `GET /v3/catalog/xref` | 第三方数据库编号（VNDB 等）→ 作品 id，不是 canon 的事实 |
| `GET /v3/catalog/works/{id}/rating-summary`、`/rating-dimensions` | 评分汇总；各媒介的子维度 |
| `GET /v3/catalog/schemas` | 每类实体由哪些字段组成、词表、谁能写，编辑台据此渲染 |

## 用户态（`/v3/me`，用户令牌）

- 状态 `wish / in_progress / done / on_hold / dropped`、卷进度、评分、每用户变更流（含墓碑）。写入带 `observed_at`，输给更新的写入时回 409 和当前状态。
- v3 的评分只开放给 canon 的作品，子维度按媒介：轻小说 6 个、漫画 6 个，每项 1–10、可不填。
- **收藏夹、浏览历史继续用 `/v2`**：`catalog_work_directory` 视图让 v2 的收藏夹、状态、历史、动态都认 canon 作品。v2 的评分与游玩时长只认旧库作品（外键、游戏专用）。

## 编辑、审核与采集（员工令牌）

权限在权限控制台的 `canon` 域，只认全局角色：

| 键 | 能做什么 | 默认 |
|---|---|---|
| `canon.edit` | 直接写 canon（`POST /commits`）、看修订、撤销一次提交 | moderator / admin / ren |
| `canon.todo.value` | 裁决首轮审核、来源矛盾、取值待办 | 同上 |
| `canon.todo.identity` | 裁决身份待办 | 同上 |
| `canon.patrol` | 巡查采集程序的写入 | 同上 |
| `canon.merge`、`canon.takedown` | 合并与撤销、下架与恢复 | 同上 |
| `canon.ingest_manage` | 设置程序模式 `review` / `auto` / `stopped` | admin / ren |

- **写入**：`POST /v3/catalog/commits` 一次提交一组改动，全部成功或全部不写。带 `expect_version` 的，版本对不上回 409 `VERSION_CONFLICT`。新建的作品、人物名义、组织像已有条目时回 409 `IDENTITY_UNSURE` 和 `candidates`：引用其中一个、沿用旧 id（`adopt_id`），或在 `distinct` 里写明不是。人写的字段采集不能覆盖，只能进待办。
- **撤销**：`POST /commits/{batch}/undo` 整次撤回。之后又被写过、引用或被用户收藏的，整次拒绝并列出原因。撤回采集写入的字段会锁定。
- **审核队列**：`GET /todos`、`/todos/{id}`（每个值带原文摘录，身份问题带候选）、`accept`（回答问题、去掉某项）、`reject`。批准以采集程序的名义写入，并记审核人。
- **巡查**：`GET /patrol` 是没人看过的采集提交；`POST /patrol/{batch}` 只做标记，不改值。

## 采集一侧

采集在独立仓库，按 `internal/canon/contract/contract.json` 写数据池；`canon fanin` 拉取、重新校验、判身份、写入或进待办，方向永远是生产调池。程序默认「逐条审核」。
