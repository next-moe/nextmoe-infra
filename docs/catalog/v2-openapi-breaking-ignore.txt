# Declared breaking changes for docs/catalog/v2-openapi.yaml.
#
# oasdiff --err-ignore matches by SUBSTRING: an entry suppresses a breaking
# change when the entry line CONTAINS oasdiff's own error text verbatim
# ("in API <METHOD> <path> <description>"), so prose may surround an entry but
# never interrupt it. Lines that match nothing — this header included — are
# inert. Removing an entry re-arms the gate for that change.
#
# D35 (2026-08-25, the GA wave — the first change through this gate for v2):
# the two moderation decision routes shared one Go input struct, so each
# advertised the OTHER route's decision values. The shared enum said
# approve|decline|merge on both operations while the doc string partitioned
# them ("Claim: approve or decline. Proposal: merge or decline.") and the
# services rejected the cross values at runtime as invalid decisions. D35
# splits the input per route, so each enum now lists exactly what its route
# accepts (claims additionally gained ban|unban — additive, no entry). Nothing
# a working client could send stopped working; a value that was schema-valid
# but always rejected is now rejected one layer earlier, by the schema.

in API POST /v2/moderation/claims/{id}/decisions removed the enum value `merge` of the request property `decision`
in API POST /v2/moderation/proposals/{id}/decisions removed the enum value `approve` of the request property `decision`

# W3 (2026-08-28, the consumer-contract wave): If-Match becomes required on the
# five operations that already hard-reject its absence. requireIfMatch has
# answered 428 PRECONDITION_REQUIRED on every one of these since they shipped,
# while the document published the header as optional — so this entry declares a
# change to the DOCUMENT, not to the server: no request that worked before stops
# working, and no request that failed before starts. It is the reverse of the
# usual breaking change, and it is the reason letmoe's withdraw button
# (catalogv2/me.go:155, an `etag` parameter its transport has no slot to send)
# is 428 on every click today while a spec-generated SDK would faithfully repeat
# the same omission.
#
# PATCH /v2/me/news/{id} is deliberately NOT in this list: its If-Match is
# required only for the withdraw transition (me_news.go:152) and optional for a
# text edit, so `required: true` there would be a false statement.

in API PATCH /v2/me/claims/{id} the `header` request parameter `if-match` became required
in API PATCH /v2/me/proposals/{id} the `header` request parameter `if-match` became required
in API POST /v2/me/proposals/{id}/amendments the `header` request parameter `if-match` became required
in API POST /v2/moderation/claims/{id}/decisions the `header` request parameter `if-match` became required
in API POST /v2/moderation/proposals/{id}/decisions the `header` request parameter `if-match` became required

# News partner obligations (2026-09-08): repr.NewsSubmission shipped `banner_hash`,
# a bare image content hash, which B10 (01-axioms.md) forbids and 04 §7 replaces
# with the one Image type -- "永远发完整 url". The four /v2/me/news responses now
# carry `banner` (url + hash) instead, so the four entries below declare the
# removal of the bare hash.
#
# No working client stops working, and that is measured rather than assumed: the
# write face has never been used. Of 4,608 rows in news_item, 0 carry the `api_`
# external_id prefix that marks a native submission -- every item came from the
# hihyou (4,573) or ymgal (35) ingest job. Keeping the field alongside `banner`
# was the alternative and it is the worse one: it would leave a standing axiom
# violation on the wire forever to protect a consumer that does not exist.
#
# The public face /v2/news gained `banner` and `source.homepage_url` in the same
# wave and needs no entry -- both are additive, and 07 §3.2 makes additions safe
# under GA.

in API GET /v2/me/news removed the required property `items/items/banner_hash` from the response with the `200` status
in API POST /v2/me/news removed the required property `banner_hash` from the response with the `201` status
in API GET /v2/me/news/{id} removed the required property `banner_hash` from the response with the `200` status
in API PATCH /v2/me/news/{id} removed the required property `banner_hash` from the response with the `200` status

# Nullability (2026-09-18): every non-omitempty pointer-to-struct field is
# published as anyOf [$ref, {type: null}] and every nullable enum lists null.
# The document now admits nulls the server has always sent; no request or
# response changes. oasdiff reads the anyOf wrapper as a type change to `any`
# and as the removal of every required property underneath it, hence the
# length. These lines only have to hold for the one transition: once the base
# document carries the wrapper nothing here can recur, and left in place they
# would also match a later, genuine removal of a field under these paths. The
