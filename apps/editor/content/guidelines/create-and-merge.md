资料库里最难收拾的不是错别字，而是**重复条目**：同一部作品建了两次、同一个人分成两个人物、同一个厂商出现三份。重复会让评分、收藏、关联、制作人员全都被拆散。这一篇讲怎样避免制造重复，以及发现重复时怎么处理。

## 新建之前先搜索 {#search-first}

新建任何条目前，先在编辑台顶部的搜索框，或对应列表页（[/works](/works)、[/characters](/characters)、[/companies](/companies)……）里搜一遍：

- 用原文名搜，也用中文名、罗马字、常见简称各搜一遍；
- 作品记得搜系列里的其他作品——你要找的可能是另一个版本；
- 人物和署名名搜所有已知的笔名。

> [!IMPORTANT]
> 搜不到不等于不存在。资料源导入的条目可能用的是另一种写法（例如日文汉字与简体字、全角与半角）。至少换两三种写法再搜。

## 新建的入口与规则 {#creating}

顶栏的「+」菜单和各列表页的「新建」按钮都能进入新建页面（`/new/<类型>`）。新建本身也是一条提案，计入提案额度，按[角色、权限与配额](/guidelines/roles-and-quotas)里的规则审核。

| 类型 | 说明 |
|---|---|
| 作品 | 走「认领」流程（`/new/work`）：填显示名、原语言、原文标题、资料站链接、发售日期。**如果填写的资料站链接已经对应到某部作品，会直接认领那部作品而不是新建。**目前只能新建 Galgame 类型的作品。 |
| 发行 | 必须挂在一部已存在的作品下，从作品的「发行」分区或作品详情页进入 |
| 角色、厂商、系列、引擎、署名名 | 任何人都可以新建 |
| 人物 | 从一个**还没有归属任何人物**的署名名建立（人物总是由署名名「长」出来的，见[署名名与人物](/guidelines/credit-names-and-persons)） |
| 标签、特质 | 只有审核者可以新建 |

### 疑似重复提示 {#duplicate-suspects}

提交新建时，系统会把名称规范化（统一大小写、全角半角等）后和已有条目比对。如果有同名条目，会弹出「疑似重复」列表：

- **逐个点开看**：是不是同一个东西？
- 确实是同一个：取消新建，去编辑已有的条目。
- 确实不是（例如同名的两个不同角色）：确认后继续新建，并在修改说明里写清楚它和同名条目的区别。

作品的查重只和**同一媒介**的作品比较；认领已有作品时不触发查重。

## 什么算「同一个」 {#what-counts-as-same}

这是最容易判断错的地方。原则：**看它在现实中是不是同一个东西，而不是看名字像不像。**

| 情况 | 是否同一条目 | 应该怎么处理 |
|---|---|---|
| 同一部作品的普通版、限定版、下载版 | 同一部作品 | 一部作品，多个[发行](/guidelines/releases) |
| 重制版、移植版（内容有明显增改） | 不同作品 | 分开建立，用[关联作品](/guidelines/relations-and-series)标记「重制」 |
| FanDisc、续作、外传 | 不同作品 | 分开建立，用关联作品标记 |
| 合集（收录多部作品） | 不同作品 | 合集单独一部，用「收录」关联到各作品 |
| 同一位画师用了两个笔名 | 同一个人物 | **一个人物、两个署名名**，不要建两个人物 |
| 两位不同的声优恰好同名 | 不同人物 | 分开建立，在备注里写区分信息 |
| 同一角色出现在续作里 | 视情况 | 续作里的那份角色条目用「实例归属」指向主条目（见[角色](/guidelines/characters)） |
| 厂商改名（公司没变） | 同一个厂商 | 一个厂商，旧名作为别名，或用厂商关系「曾用名」 |
| 品牌从母公司独立 | 不同厂商 | 分开建立，用厂商关系标记 |

## 合并请求 {#merge-requests}

发现两个条目其实是同一个东西时，在其中一个条目的详情页点「合并」，发起**合并请求**：

1. 选择方向：哪个被并入、哪个保留（通常保留资料更完整、被引用更多的那个）；
2. 写理由（必填，至少几个字）：为什么认为它们是同一个，有哪些依据；
3. 提交后进入合并请求队列，由拥有合并审核权（`catalog.merge.review`，默认 moderator、admin、ren）的人决定。

可以发起合并请求的类型：作品、厂商、角色、人物、署名名。**不同媒介的两部作品不能合并**（例如游戏和它改编的动画），系统会直接拒绝——它们本来就是不同的作品，应该用关联作品连接。

### 合并请求的流程 {#merge-lifecycle}

| 阶段 | 说明 |
|---|---|
| 待审核 | 你可以在 [/me/merge-requests](/me/merge-requests) 撤回 |
| 已批准（冷静期） | 审核者批准后，要等待一段冷静期（默认 48 小时，`catalog.merge_cooling_off_hours`）才会执行。这段时间留给大家发现问题；如果你发现不该合并，立刻联系审核者 |
| 已合并 | 冷静期结束后由每小时运行的任务自动执行，或由审核者手动执行 |
| 已驳回 | 审核者认为不该合并 |

合并请求也有额度（默认普通用户 24 小时内 10 次，见[配额](/guidelines/roles-and-quotas#quotas)）。

### 合并之后会发生什么 {#after-merge}

- 被并入的条目变成**重定向**：旧链接、旧编号仍然能访问，会跳到保留的条目；
- 两边的资料、外链、关联、收藏、评分并到保留的条目上，保留方原有的资料优先；
- 被并入条目上待审的提案会被自动拒绝（条目已经不存在了）；
- 隐藏记录、人工修改随之迁移；
- 合并前的状态会存档。**撤销合并**目前只能由管理员在管理台操作。

> [!CAUTION]
> 合并很难完美撤销：撤销会尽力复原，但合并之后在保留条目上发生的修改不一定能分回去。拿不准的合并请求，宁可在理由里写明疑点让审核者判断，也不要「先合了再说」。

## 常见错误 {#common-mistakes}

| ❌ 做法 | 后果 | ✅ 应该 |
|---|---|---|
| 没搜索就新建作品 | 制造重复，评分收藏被拆散 | 多种写法搜索后再建 |
| 把限定版建成单独的作品 | 重复作品 | 建成同一作品下的发行 |
| 把同一个人的笔名建成两个人物 | 作品履历被拆散 | 一个人物下挂多个署名名 |
| 对游戏和它的动画发起合并 | 被拒绝 | 用关联作品「改编」连接 |
| 合并理由只写「重复」 | 审核者无法核实 | 写出依据：同一个外部条目、同一张包装、官方说明…… |
| 疑似重复提示直接点继续 | 制造重复 | 逐个点开核对 |
