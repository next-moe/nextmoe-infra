## 两层信息：厂商本身 vs. 厂商在作品中的身份 {#two-layers}

| 层次                   | 在哪里改                                       | 例子                                             |
| ---------------------- | ---------------------------------------------- | ------------------------------------------------ |
| **厂商在作品中的身份** | 作品工作区「厂商」分区，右栏上半部分           | Key 在《Summer Pockets》里是「开发」还是「发行」 |
| **厂商本身**           | 同一个右栏下半部分的标签页，或厂商自己的编辑页 | 厂商的名称、类型、别名、母子公司关系、Logo       |

作品中的身份（开发 / 发行 / 品牌 / 社团）见[厂商、引擎与平台](/guidelines/companies-engines-platforms)。本篇讲厂商条目本身。

> [!NOTE]
> 厂商是多部作品共用的条目，**所有人的修改（包括审核者自己的修改）都要经过另一位审核者确认**才会生效。

## 名称、罗马字与语言 {#name}

| 字段   | 填什么                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------- |
| 名称   | 厂商的官方名称原文，例如「ビジュアルアーツ」或「Key」。用这个厂商自己在官网、作品包装上使用的写法 |
| 罗马字 | 名称的罗马字或官方英文写法（可选）                                                                |
| 语言   | 名称本身的语言                                                                                    |
| 备注   | 给其他编辑者看的说明，例如「与同名的动画公司不是同一家」                                          |

中文译名、旧名称、常见简称写在「别名」里，不要塞进名称。

## 类型 {#kind}

| 类型     | 用于                         |
| -------- | ---------------------------- |
| 游戏品牌 | 制作发行游戏的品牌，例如 Key |
| 文库     | 轻小说文库                   |
| 出版社   | 出版发行商、发行公司         |
| 动画公司 | 动画制作公司                 |
| 同人社团 | 同人社团、个人社团           |
| 团体     | 不属于以上几类的团体         |

按这个厂商**主要从事的业务**选。一家公司旗下的不同品牌是不同的厂商条目，各自选自己的类型，再用「厂商关系」连起来。

## 别名 {#aliases}

别名记录同一家厂商的其他叫法：中文译名、旧写法、全半角差异、简称等。每条别名有名称、语言、类型（译名 / 异写），可选罗马字和「该语言主名」。

资料源导入的别名可以单独隐藏；已经由资料源提供的别名不要再手动添加，系统会拒绝并提示改用隐藏。

> [!WARNING]
> **改名**不等于别名。如果厂商更名后作为新的公司继续经营（新的法人、新的品牌），应该是两个厂商条目，用「前身」/「继任者」关系连接；只是写法变化或简称，才放进别名。

## 厂商关系 {#relations}

厂商关系描述两家厂商之间的关系，例如母子公司、旗下品牌、前身。每条关系由「对方厂商」和「关系」组成，**关系描述的是对方相对本厂商的身份**：

| 界面显示   | 含义                                                                    | 例子（在「ビジュアルアーツ」的条目里） |
| ---------- | ----------------------------------------------------------------------- | -------------------------------------- |
| 母公司     | 对方拥有本厂商                                                          | ——                                     |
| 子公司     | 本厂商拥有对方                                                          | 对方：某子公司                         |
| 旗下品牌   | 对方是在本厂商名下经营的品牌                                            | 对方：Key                              |
| 所属品牌方 | 本厂商是在对方名下经营的品牌（在 Key 的条目里，对方选ビジュアルアーツ） | ——                                     |
| 分出       | 对方是从本厂商分出去的                                                  | 对方：独立出去的新品牌                 |
| 分出自     | 本厂商是从对方分出来的                                                  | ——                                     |
| 继任者     | 对方继承了本厂商（本厂商后来变成了对方）                                | ——                                     |
| 前身       | 本厂商继承了对方（对方是本厂商的前身）                                  | ——                                     |

要点：

- **关系会同时写到对方厂商上。** 你在ビジュアルアーツ里添加「旗下品牌：Key」，Key 的条目里会自动出现反方向的「所属品牌方：ビジュアルアーツ」。所以只需要在一边添加。
- 不能把厂商和自己建立关系；同一对厂商之间同一种关系只能有一条。
- 资料源导入的关系可以隐藏；隐藏会同时作用于两边。一条关系如果在任意一方被隐藏了，要先在一次单独的修改里取消隐藏，才能再人工添加。
- 关系的方向容易弄反：添加前把它读成一句话——「**对方**是本厂商的旗下品牌」——读得通再提交。

## Logo {#logo}

上传厂商的官方 Logo，最好是透明背景、比例正常的版本。不要用截图截下来的模糊 Logo，也不要用作品的标题 Logo 代替厂商 Logo。

## 简介与外链 {#intros-and-links}

- **简介**：每种语言一段，介绍厂商的成立时间、主要作品与经营情况；人工简介优先于资料源导入的版本显示。
- **外链**：填完整网址，主要是官网、官方社交账号、商店里的品牌页。资料源导入的外链可以单独隐藏；同一个网址不要重复添加。

## 新建与合并 {#create-and-merge}

- 新建厂商前先搜索（包括别名），避免重复。系统发现同名的可疑重复时会提示你确认。
- 发现两个条目其实是同一家厂商（例如一个是罗马字名、一个是日文名），发起**合并请求**，不要把其中一个的资料清空。详见[新建条目与合并重复条目](/guidelines/create-and-merge)。

## 常见错误 {#common-mistakes}

| ❌ 错误做法                                                      | ✅ 正确做法                                 | 原因                           |
| ---------------------------------------------------------------- | ------------------------------------------- | ------------------------------ |
| 在作品的厂商分区把「发行」改成另一家公司，却去改了厂商本身的名称 | 在作品里换成正确的厂商条目                  | 改名称会影响这家厂商的所有作品 |
| 名称写「Key（ビジュアルアーツ）」                                | 名称只写「Key」，用关系连接ビジュアルアーツ | 名称只放厂商自己的写法         |
| 关系方向弄反（在 Key 里写「旗下品牌：ビジュアルアーツ」）        | 在 Key 里写「所属品牌方：ビジュアルアーツ」 | 关系描述的是对方的身份         |
| 在两边各添加一次同一条关系                                       | 只在一边添加                                | 关系会自动写到对方             |
| 公司改组成新法人后，只把新名字加成别名                           | 新建厂商并用「前身」/「继任者」关系连接     | 两个时期是不同的经营主体       |
| 用作品标题 Logo 当厂商 Logo                                      | 用厂商自己的 Logo                           | Logo 代表厂商本身              |
